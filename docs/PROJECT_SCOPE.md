# ParamGuard Vision 项目范围基线

| 字段 | 值 |
|---|---|
| 文档状态 | 个人学习 PoC 的设计基线，非生产 SOP |
| 版本 | 0.1 |
| 基线日期 | 2026-08-25 |
| 数据级别 | 仅纯合成数据，或未来经明确授权且可证明脱敏的数据 |
| 项目定位 | 研究图像参数核验的独立个人 PoC |

## 1. 问题定义

设想的业务场景是：第一审核员逐项对照“照片 A”与“系统截图 A'”中的参数；人工记录全部完成并锁定后，系统才运行或显示 OCR/视觉 AI 的辅助结果。面试题设匹配的默认档案把普通异常交给锁后定向人工复核，把结构/系统问题交给 QA；只有在另一已批准 SOP/风险档案明确要求时，才对全部字段启用与 R1 身份分离的盲二审。任一路径都不允许 AI 自动放行。

本项目研究的不是“让 LLM 替人批准”，而是以下工程问题：

- 如何在后端强制人工先独立作答，不向首审员泄露 AI 线索；
- 如何用确定性规则处理字符级完全一致，而不让概率模型承担最终精确判定；
- 如何将异常保守分流，并保留可重建的证据时间线；
- 如何用隐藏测试集衡量差异召回率和假阴性率，而不只看 overall accuracy。

## 2. 预期用途

ParamGuard Vision 仅用于学习和演示下列能力：

1. 导入一对合成照片/截图及固定版本的模板和 Schema；
2. 创建带唯一 ID 和证据哈希的核验任务；
3. 收集、完整性检查并锁定首审员的逐项结论；
4. 在人工锁定后运行 OCR/视觉辅助提取；
5. 保留原始字符串，进行可重复的确定性比较；
6. 按显式、带版本的流程档案，把风险信号路由到定向人工复核、条件性全字段盲二审或 QA；
7. 导出明确标注为“辅助核验、非放行决定”的报告与评估指标。

## 3. 系统边界

### 范围内

- 本地优先、纯合成数据的端到端演示；
- 图像质量门、固定 Schema/模板、OCR 和参数对齐；
- 严格保留原始表示的确定性比较器；
- 人工首检、锁定门、AI 后检、保守分流、定向异常复核、条件性全字段盲二审和 QA/仲裁；
- 追加式事件、证据哈希、版本标识和可重建时间线的 PoC；
- 正常、边界、对抗和隐藏样本测试。

### 范围外

- 批次放行、产品放行、偏差结案或任何具法律/质量授权的电子签名；
- 自动修改 OT 设备参数，或写入 MES、DCS、SCADA、PLC、LIMS 等生产系统；
- 把 AI 结论当作真值，用 AI 覆盖人工记录，或自动关闭异常；
- 动态在线学习、未受控模型更新或网络依赖的自主代理；
- 真实患者、生产、批次、设备、员工或企业数据；
- 企业内部系统、内部流程、SOP 或受委托项目的复刻；
- 法规认证、GxP 验证、Part 11 合规证明或生产部署。

## 4. 角色与决定权

| 角色 | PoC 内职责 | 不得做的事 |
|---|---|---|
| 首审员 | 独立核对全部预期参数并锁定记录 | 锁定前查看 AI 结果；锁定后覆盖原记录 |
| 定向复核员 | 在面试档案中仅复核服务端从冻结事实重算出的异常字段 | 自由删减异常、将复核结果当成放行，或冒充已完成全字段盲审 |
| 独立盲二审员 | 仅在已批准档案选择该路径时，对冻结的全 Schema 独立作答并锁定 | 与首审员使用同一身份，或在锁定前查看 R1/AI/路由线索 |
| QA/仲裁角色 | 处理结构异常、未解决分歧和流程异常 | 将 PoC 的路由标签当作真实放行 |
| OCR/视觉 AI | 辅助提取、对齐、标记不确定和生成说明 | 改写人工决定、自动放行或关闭偏差 |
| 确定性规则引擎 | 处理字符级比较和保守分流 | 判定参数本身合法，或做出质量放行决定 |

## 5. 项目级强制决定

下列是本 PoC 自己的设计决定，不声称它们是所有制药企业都必须采用的法定流程：

- `PD-HF-01`：默认严格顺序，首审员锁定后才可启动 AI/OCR；
- `PD-HF-02`：未来的“密封并行”只能在明确 SOP、记录化风险评估、授权和变更控制后开启；
- `PD-DET-01`：完全一致由确定性程序按原始字符判断，LLM/VLM 不做最终精确判定；
- `PD-ESC-01`：有风险信号时宁可升级，不自动推定为通过；
- `PD-PROFILE-01`：锁后人工路径由已批准、带版本且内容哈希的 profile 决定；面试档案的普通异常采用定向复核，全字段盲 R2 不是默认法规要求；
- `PD-DATA-01`：只使用合成或有授权且经证明脱敏的数据，默认本地处理；
- `PD-CLAIM-01`：测试通过只证明已测功能在当前环境下符合预期，不等于 GxP/Part 11 验证。

## 6. 成功指标

项目首先优化“不漏掉真实差异”，因此主指标是差异召回率和假阴性率。配套指标包括字段提取率、对齐错误、缺失/多余检出、拒答率、人机分歧率、每任务人工用时和报告生成时间。所有性能声明必须绑定数据集版本、分组、样本数、阈值和完整结果；未测量前不声称提效百分比。

## 7. 生产化前置条件

从本 PoC 到任何真实环境不是“直接部署”。至少需由拥有者组织完成：实际流程和记录的法规适用性评估、批准的 intended use、数据分类、SOP 对齐、质量风险评估、供应商评估、计算机化系统验证/保证、安全架构、身份与电子签名控制、备份/恢复、业务连续性、培训、变更控制和运行监督。详见 [REGULATORY_APPLICABILITY.md](./REGULATORY_APPLICABILITY.md) 和 [HUMAN_FIRST_URS.md](./HUMAN_FIRST_URS.md)。

## 8. 可选辅助工作区（2026-08-28）

以上首审、R1/R2 与档案约束适用于默认 `STRICT_SEQUENTIAL` 流程。新增 `ASSISTED_REVIEW_V1` 是用户明确选择的独立实验入口：先从上传的合成图片中定位目标、显示 OCR 观察，再逐项记录人工结论。它不能作为必须先独立人工首审的替代品。

- 独立模块 `paramguard.assisted_web`、独立 SQLite 工作区、不可变模式标识；不向严格流程写入或导入 R1/R2/QA 记录。
- 目标清单在开始前冻结，全部目标始终保留；未找到、重复、低置信与差异不会因筛选而从核验范围中消失。
- 仅处理 PNG/JPEG 与受限单列 ASCII 编号。机器候选不是已确认的正确定位；人工可选候选或指定值区域，并使该项当前人工记录失效、要求重审，旧记录保留在历史中。
- `REVIEW_COMPLETE` 只表示每个目标都有人工填写的记录，包含“无法判断”；不表示全部正确、异常关闭、QA 完成或获准放行。页面没有自动批准接口。
- 上传仅限有权使用的合成测试数据。允许选择本机文件不等于允许公司/患者数据进入 PoC，更不等于可以把图片上传 GitHub。

使用方式与已知限制见[辅助工作区](./ASSISTED_WORKBENCH.md)。默认流程的人工锁前零 AI 信息要求保持不变。

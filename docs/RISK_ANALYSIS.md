## 1. 评分规则

- **影响高**：可能将真实差异隐藏为一致、伪造人工/审计证据、导致未授权批准，或对受规制记录/数据完整性造成重大影响。
- **影响中**：主要造成额外人工、延误、可恢复错误或局部可用性问题，但在当前 fail-closed 设计下不应静默通过。
- **可能性**和**可检出性**只是当前合成 PoC 判断，不能沿用到真实工厂。
- **残余风险**为“尚未可接受/需人工升级”时，系统不得通过一个更乐观的模型分数自行关闭风险。

## 3. 在“必须人工先检”下可以安全提效的部分

题设不允许用 AI 代替或预先影响 R1，因此第一阶段不应承诺“少看多少项”。可以优先减少的是**非判断性工作**：

1. 用人工批准的固定模板预先将 A/A' 的同一字段 ROI 并排，同时保留一键回到整图上下文；
2. 使用明确、不默认的快捷键记录 `SAME`/`DIFFERENT`/`UNABLE_TO_JUDGE`，自动跳到下一未作答字段；
3. 服务端做完整度检查、重复/跳项防护、稳定顺序、进度显示、锁前确认和可恢复草稿；
4. 将所有 `DIFFERENT/UNABLE` 理由用固定类别+简短文本记录，减少重复输入但不预填结论；
5. 用服务端时间测量每字段/任务耗时、回退次数和未完成数，识别 UI 瓶颈，但不记录键盘内容等无必要数据；
6. R1 锁定后才运行本地 OCR，将冻结事实按已批准 profile 组织成清晰的定向异常复核、条件性全字段盲 R2 或 QA 队列；
7. 报告和审计时间线自动生成，避免人工复制粘贴，但报告始终标记“辅助、非放行”。

这些改动可以降低翻找、滚动、对齐、重复输入和查漏耗时，同时不改变面试题设中“R1 亲眼核验全部必检字段”的公司约束。任何减少人工检查范围、只看 AI 异常或密封并行的改动，都需要真实 SOP、质量风险评估和授权，不在本 PoC 自行假设。

## 4. 下一次风险复审触发条件

出现以下任一情况时必须更新本文档：

- 新增或将 OpenCV/动态配准、PaddleOCR/docTR challenger、LLM/VLM 接入主管道、真实数据或网络 transport；
- 新增真实上传、网络 API、数据库、队列、对象存储、IdP 或电子签名；
- 允许在 R1 锁定前运行任何与证据相关的计算；
- 将 `NO_EXCEPTION_DETECTED` 、QA outcome 或任何模型输出用于真实放行/偏差决定；
- 引入非合成数据、真实公司流程或外部云处理；
- benchmark 出现任一假阴性、不可解释的性能漂移或审计/身份绕过；
- 官方法规/指南、开源许可证或依赖安全状态发生变化。

# 本机图片核验工作区

`ASSISTED_REVIEW_V1` 用来把两组图片中的指定参数整理到同一核对页面。它先显示机器候选，再收集人工记录，**不是独立人工首审**。如果流程要求先由人员独立核验，请使用原来的 `paramguard.webapp`，不要使用此入口替代。

## 启动

需要 macOS / Linux、Python 3.11+、Pillow、Tesseract 和 `eng` 语言数据。项目没有新增 Python 依赖；Tesseract 需要单独安装。确认 `tesseract --list-langs` 包含 `eng` 后，在已安装本项目的环境中运行：

```bash
python -m paramguard.assisted_web --port 8766 --workspace artifacts/my-workspace
```

打开 <http://127.0.0.1:8766/>。程序只绑定本机地址，不应通过代理转发到公网。停止后使用相同 `--workspace` 启动，可以从右上角打开历史任务。两份进程不能同时打开同一工作区。

## 输入是什么

两侧分别可以上传多张 PNG/JPEG。按目标编号配对，不要求照片和截图张数相同，也不按文件顺序把行硬配在一起。这里的“照片 A”是来源名称，不表示已经验证任意实拍照片的效果。

首版的自动定位假设：**单列、逐行布局，每行第一个连续英文/数字编号，后面是值和单位**，例如：

```text
P000001    100.01 kPa
P000002    100.02 kPa
```

中文编号、手写、多列、合并单元格、跨行或分词编号不在已验证范围内。OCR 没找到一个编号，不代表原图中没有它。

目标清单支持以下两种输入：

```text
P000001
P000021
```

```csv
parameter_id,label
P000001,Inlet pressure
P000021,Outlet pressure
```

大小写和前导零保留；重复目标会被拒绝。纯文本中的 `id` 和 `parameter_id` 是合法目标，不会被静默当作表头。CSV 表头仅识别明确的两列格式。只粘贴编号，不要粘贴预期正确值；目标真值不进入 OCR。

## 操作流程

1. 选择两侧文件，填写任务名和目标清单。勾选非盲辅助模式、合成测试数据和单列布局确认。
2. 点击“创建并定位参数”。先保存并校验所有图片，再冻结目标、图片哈希和识别配置，逐页运行本地 OCR。
3. 全部图片处理结束后，查看完整目标清单。25 项一页；搜索、筛选不会改变目标总数或完成条件。
4. 逐项查看两侧编号、值、单位和上下文。机器的相同/不同只针对识别文字，不能代替看图。
5. 记录“相同”“不同”或“无法判断”。不同、无法判断、推翻机器提示时必须写原因。快捷键为 S / D / U；输入框中不会触发快捷键。
6. 全部目标有记录后，才可“完成人工记录”。完成前校验审计投影和每张图片的字节哈希；完成后任务只读。
7. “导出记录”下载 JSON，包含完整目标、机器观察、人工记录、图像与区域摘要和事件历史，不包含图片字节。

`REVIEW_COMPLETE` 不表示所有参数相同，也不表示批准。机器差异、无法判断和历史记录仍在；本入口没有 QA、电子签名或放行功能。

## 找不到、重复、读不清时

| 状态 | 含义 | 可做的操作 |
| --- | --- | --- |
| 未定位 | 至少一侧没有候选；可能是 OCR 漏读 | 查看原图，确认编号后手动框选值与单位；不能确认则记“无法判断” |
| 多个候选 | 同一侧出现重复编号或重叠来源 | 下拉查看全部候选，在原图确认后明确选择；系统不按最高分自动决定 |
| 识别不确定 | 低置信、无值、串列疑似或区域多行 | 看原图并重新定位，或保留无法判断；不能把置信分当作正确概率 |
| 机器提示差异 | 识别字符串不相同 | 查看高亮与原图；可能是真差异，也可能是 OCR 错字 |

手动定位可以拖出矩形，也可以填写原图像素坐标。只选择当前编号对应的**值与单位**；编号与邻近行需要自己先确认。方向校正后的图是唯一坐标系。更换候选或区域会使这一项当前人工记录失效，旧记录留在事件历史中，必须重新复核。

## 数据、错误与恢复

- 原始文件和去除元数据的方向校正 PNG 一起保存在本机 SQLite。原文件可能仍带有原来的 EXIF 等元数据；界面去除元数据不等于数据库做了匿名化。
- 同一来源的字节哈希、校正图哈希和区域哈希随任务保存。损坏、透明、多帧、越界、过大或格式不符的图片会被拒绝，不自动“修好”后冒充原图。
- 数据确认是用户声明，不是自动敏感信息识别。不要上传公司、患者、凭据或个人敏感材料。GitHub 只包含项目代码和明确的合成样例。
- 每个写操作带任务、清单哈希、修订号和幂等命令标识。过期页面会被拒绝；网络重试不应产生第二份同一记录。
- 完整任务索引失败时不会把已处理的部分候选标为 READY。中断后重启标为 `INTERRUPTED`，不会暗中继续旧的未完成索引；应新建任务重新处理。
- 导入失败后已接纳的图片仍在草稿中。刷新或从历史打开草稿，补齐文件，再开始。开始后不能替换原图或目标。
- 完成后的任务不能直接改写。需要修订时新建任务。此版没有页面内删除或自动保留期清理功能；备份、恢复和清理需先停止工作区进程，再按本机文件管理策略处理整个目录。不要只删除 SQLite 的一部分文件。
- 审计哈希链能帮助核对历史关系，但不能防止有磁盘权限的人重写整个库，也没有独立签名锚或 WORM 存储。没有真实登录；此版不适合作为多人审核服务。

## 当前资源上限

| 对象 | 上限 |
| --- | --- |
| 每任务目标 | 2000 个 |
| 每侧图片 | 64 张 |
| 原始图片 / 校正 PNG | 8 MiB / 16 MiB |
| 单图像素 / 单边长度 | 1600 万 / 16000 像素 |
| 任务图片总字节 | 256 MiB，原始文件与 PNG 合计 |
| 工作区图片总字节 | 512 MiB，非整个数据库的硬磁盘配额 |
| 任务总像素 | 5.12 亿 |
| 每页 OCR 输出 | 4 MiB，最多 40000 个词 |
| 单侧每目标候选 | 64 个 |
| 工作区任务 / 每命令作用域收据 | 64 / 40000 |
| 单次 OCR / 整轮索引预算 | 30 秒 / 300 秒；总预算在页间及发布前检查 |

一次工作区只运行一个 OCR 操作，HTTP 并发最多 4 个请求。停止索引需等待当前受限 OCR 返回。总预算可能被最后一页占用的时间超出，但超预算结果不会接纳；图像解码仍在服务进程内，没有独立 CPU/RSS 沙箱。拆图有助于控制尺寸，不能提升原本缺失的图像细节。

## 实现与验证边界

UI、HTTP 入口和工作区分别位于 `static/assisted.html`、`assisted_web.py`、`assisted.py`；图片和 TSV 解析在 `assisted_input.py`。原严格流程没有导入这些模块，辅助记录也不能转成严格 R1。

固定的识别设置是 Tesseract `eng`、PSM 6、置信门槛 70。TSV 按页/块/段/行分组，首词精确匹配编号，不纠正 O/0 或 I/1，不按邻近行补编号。行不是通用表格结构；这些限制与 [Tesseract 官方 TSV 说明](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html#tsv-output)及[表格识别限制](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html#tables-recognition)一致。

即使编号字符串匹配，OCR 也可能把一个合法编号误读成另一个。比较时不转换数值、单位或大小写，但 OCR 词之间的空格是重建的，不能保证图片中空格完全相同。见[实测与失败样例](./ASSISTED_BENCHMARK.md)和[完整网页演示](./demo/WALKTHROUGH.md)。

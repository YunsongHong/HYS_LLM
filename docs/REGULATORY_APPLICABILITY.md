## 1. 当前结论

**ParamGuard Vision 当前是使用纯合成数据的本地个人学习 PoC，不在真实制药质量系统中创建、维护、批准或依赖任何法定/GMP 记录。** 因此，本项目只能说“参考官方法规与指南进行风险导向设计”，不能说“已符合 GxP”、“Part 11 compliant”或“通过验证”。

是否适用 FDA Part 11、药品 CGMP、EU GMP Annex 11 或某个企业 SOP，不由项目名称、用了 AI，或客户是药企这些信息单独决定。必须先确定辖区、产品、活动、实际 intended use、数据关键性、哪些记录是 predicate-rule/GMP 记录，以及组织在实际业务中依赖哪个记录做决定。

## 2. 适用性判定顺序

1. **识别活动**：这是学习演示、非记录性辅助，还是真正的生产/质量活动？
2. **识别记录**：哪些输入、人工决定、比较结果、审计事件和签名必须根据适用规则保留？
3. **识别依赖方式**：组织是依赖电子记录运行受规制活动，还是仅使用符合 predicate rule 的纸质记录？`SRC-US-P11-SCOPE` 说明业务实践会影响 Part 11 判定。
4. **识别辖区和法律主体**：美国 FDA、EU GMP、其他参与 PIC/S 的机构，以及所在地要求不能混为一谈。
5. **识别系统影响**：直接 GMP 影响、间接影响还是无 GMP 影响？系统失败能否损害患者安全、产品质量、数据完整性或 OT 可靠性？
6. **识别人工与自动化责任**：谁有权记录、复核、仲裁、批准和放行？AI 输出是参考、记录还是决定输入？
7. **由正式角色批准**：输出一份组织特定的适用性备忘录，由 Process Owner、System Owner、QA/Validation、IT/OT Security 和必要的法务/监管专家审批。

## 3. 场景矩阵

| 场景 | 当前适用性结论 | 可用来做什么 | 不能做什么 |
|---|---|---|---|
| 本地合成数据学习 PoC | 无真实 GxP 记录；官方文件是设计标杆，不是已验证状态 | 演示确定性比较、人工锁定、保守分流、审计证据和评估思路 | 处理真实数据；用于放行/偏差结案；声称 GxP/Part 11 合规 |
| 不被依赖为 GMP 记录的内部辅助工具 | 仍需组织确认数据安全、隐私、网络安全和 SOP；不能从“辅助”一词假定无 GMP 影响 | 经批准后做受限的非关键提示 | 绕过正式适用性和数据分类评估 |
| 在 EU GMP 活动中使用的计算机化系统 | 可能落入现行 Annex 11（`SRC-EU-A11`）；实际范围由活动和 GMP 影响决定 | 用已批准 URS、风险评估、验证、安全、审计轨迹和变更控制建立生产系统 | 将本 PoC 测试报告当作 Annex 11 验证包 |
| 在美国药品 CGMP 活动中使用的电子系统 | 可能触发适用 predicate rules（如§ 211.68）；若以电子形式维护/依赖受要求记录，则需按 `SRC-US-P11-SCOPE` 评估 Part 11 | 使用组织特定的 predicate-rule 矩阵决定记录、签名和控制 | 因为有审计日志就声称 Part 11 compliant |
| 医疗器械生产/质量管理系统 | FDA 2026 CSA 指南（`SRC-US-CSA-DEVICE`）可能直接相关，但这不是当前药品参数场景 | 另建医疗器械特定的法规/质量范围 | 把 CSA 指南无条件套用到所有药品 GxP 软件 |
| 批次放行、电子签名或偏差结案 | 明确超出当前 PoC 的 intended use 和权限模型 | 只能在受规制组织完成独立设计、验证、身份/签名和 QA 批准后考虑 | 让 AI、路由函数或“NO_EXCEPTION_DETECTED”自动实现放行 |

## 4. Human-first 的准确定位

`PD-HF-01` 要求“首审员完成全部预期字段并锁定后，AI/OCR 才能运行或对其可见”。这是题设场景和项目风险模型下的**项目决定**，不是已证明的普遍法律要求。

现行 EU Annex 11 第 6 节要求对关键手工录入数据进行额外准确性检查，但明确允许第二位操作员或经验证的电子方式，并将控制强度交给风险管理。它没有规定本项目的人机先后显示顺序。

2025 年 Annex 22 文本只是已结束征求意见的草案（`SRC-EU-A22-DRAFT`）。其 human-in-the-loop 文字可用于前瞻设计，但不能被写成已生效的通用 human-first 规则，也没有自动证明本项目的流程选择。

## 5. 若进入真实企业的强制暂停点

遇到下列任一情况，必须停止将 PoC 直接前推，请求实际组织的 Process Owner/QA/Validation/ITOT Security 提供输入：

- 需要真实图片、设备配置、批次参数或公司 SOP；
- 系统结果将被引用到 GMP 记录、偏差、变更或放行决定；
- 需要与 MES/DCS/SCADA/PLC/LIMS 读写集成；
- 需要保留电子签名，或将其视为手写签名的法律等效物；
- 需要“密封并行”而不是默认严格顺序；
- 需要外部云服务、模型 API 或跨边界数据传输。

这些情况需要新的授权和正式评估，不能用开源项目的默认值代替。

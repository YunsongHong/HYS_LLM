# 第一课：为什么先做严格比较器

## 1. 这个项目到底在处理什么？

最小的数据单位不是“一张大图片”，而是一个参数对：

```text
左边 A：37.0 °C
右边 A'：37.0 °C
```

未来 OCR 的任务，是把图片中的文字读成这样的字符串。比较器的任务，是判断两个字符串是否完全一致。

所以完整系统可以先拆成两层：

```text
图片 → OCR 读文字 → 普通程序严格比较
```

视觉模型负责“看见了什么”，规则程序负责“是否完全相同”。

## 2. 为什么不能让 LLM 直接说相同或不同？

LLM 擅长理解意思和生成语言，但它的输出具有概率性。相同输入不一定永远得到完全相同的解释，而且模型可能把以下内容理解为“差不多”：

- `1.0` 与 `1.00`；
- `001` 与 `1`；
- `1000 μg` 与 `1 mg`；
- `AUTO` 与 `auto`。

但业务要求是“显示内容完全一致”。因此只有两个非空字符串逐字符相同，程序才给出 `EXACT_MATCH`。

但 `EXACT_MATCH` 也只说明字符相同。例如 `ERROR` 对 `ERROR` 虽然字符一致，仍不代表这是一个合法参数，更不代表可以放行。后续版本会用字段 Schema 检查类型、允许单位和取值范围。

LLM 将来可以帮助我们解释异常、理解陌生模板，不能替代这个严格比较器。

## 3. 为什么要保留原始值？

假设程序为了方便，把空格、大小写和前导零都删除：

```text
025.0 L/min → 25.0l/min
25.0 L/min  → 25.0l/min
```

这样两个值看起来相同，但程序掩盖了原始差异。

因此项目同时保留：

- `left_raw`：左侧原始值；
- `right_raw`：右侧原始值；
- `exact_match`：是否逐字符一致；
- `kind`：差异属于数值、单位、格式、文本还是缺失；
- 辅助解析值：只用于解释，不能覆盖严格结论。

## 4. 为什么使用 Decimal？

计算机中的普通浮点数不能精确表示所有十进制小数。例如：

```python
0.1 + 0.2 == 0.3
```

结果通常是 `False`。参数比较若需要解释数学数值，应使用 `Decimal`，避免把二进制浮点误差带入结果。

注意：即使 `Decimal("1.0") == Decimal("1.00")`，本项目仍将原始显示差异判定为不完全一致。

## 5. 你现在应该会什么？

完成本课后，只需要理解四句话：

1. OCR 负责从图片读文字；
2. 普通程序负责精确比较；
3. LLM 负责理解或解释，不负责最终放行；
4. 任何清洗和标准化都不能覆盖原始记录。

接下来我们才会加入“人工先提交并锁定”的状态流程。

## 6. 为什么 JSON 中的数值也要加引号？

我们核验的是屏幕上“显示出来的内容”，所以 `001`、`1.0` 和 `1.00` 必须保留为字符串：

```json
{
  "left": "001",
  "right": "1"
}
```

如果直接保存成 JSON 数字，解析器会先把它们转换成数值，原始格式可能在进入比较器前就已经丢失。
